Project 2 — Network Graph Analyzer

Graph design

I modeled eight reported Fortnite chest spawn locations on Crossbones Isle. Each chest location is a node. I chose nine connections between nearby chests to create a sample with branches and cycles. The connections are two-way, and each edge's weight is the straight-line distance between its two chests, measured in map pixels.

I stored the graph as an adjacency list using a Python dictionary. Each chest ID is a key, and its value is a list of neighboring chest IDs and their distances. If chest A connects to chest B at a distance of 5, A's list stores (B, 5) and B's list stores (A, 5). A chest with no connections has an empty list.

How the searches work

BFS explores level by level, like moving through a tree one level at a time. It uses a queue to visit the starting chest, then the chests one connection away, then the chests two connections away. It marks each chest when it goes into the queue so it only gets queued once.

DFS follows one branch as far as it can, then goes back to explore another branch. I used a stack so the most recently added chest comes out first. The visited set keeps a chest from appearing twice in the result, even if it was put on the stack more than once.

Dijkstra finds the route with the lowest total distance. It uses a priority queue to process the chest with the smallest known distance from the start. If it finds a shorter way to a neighbor, it updates the distance and records which chest led there. Once it reaches the destination, it follows those records backward and reverses the list to get the route.

Time complexity

Let V be the number of chests and E be the number of connections. Adding a node and looking up its neighbor list take O(1) time on average. Adding an edge takes O(1) amortized time because the program appends to two neighbor lists. Reading a chest's entire neighbor list takes time proportional to its number of neighbors. BFS and DFS each take O(V + E) time because they process reachable nodes and scan their connections. Dijkstra takes O((V + E) log(V + E)) time with this heap implementation, which can hold multiple distance entries for the same chest.
